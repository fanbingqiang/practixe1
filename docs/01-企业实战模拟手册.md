# 企业实战模拟手册

> 核心原则：**代码简单，流程真实。**
> 你演"入职的开发工程师"，我演"Tech Lead + 测试 + 运维 + 审代码的老同事"。
> 每一步都按真实公司流程走：有工单、有评审、有提测、有 Bug 单、有上线单、有复盘。

---

## 一、角色与职责（模拟）

| 角色 | 谁演 | 职责 |
|------|------|------|
| 产品/需求方 | 我 | 提需求单，讲清业务价值与验收标准 |

| 你偶尔要串演 | 你 | 阶段 10 之后我会让你自己评审一次"别人的代码"（我写的烂代码） |

## 二、标准迭代流程（每个阶段都跑一遍）

```
①需求单  →  ②方案+接口文档评审  →  ③开分支开发  →  ④自测(测试报告)
   ↓
⑤提交 Code Review  →  ⑥评审意见整改  →  ⑦合并主干  →  ⑧部署测试环境
   ↓
⑨提测(我出用例)  →  ⑩Bug 单流转  →  ⑪回归  →  ⑫上线单+Checklist
   ↓
⑬线上故障演练  →  ⑭复盘报告
```

**关键：第 ⑤ 步我一定会挑刺。** 真实评审会挑这些：
- 变量/方法命名不规范、缺注释
- 参数没校验（`@Valid` 缺失）、异常直接吞掉
- 硬编码魔法值、密码写死在代码里
- 事务边界不对、循环里查数据库（N+1）
- 没有测试、日志打得不全（出问题查不到）

被挑到就是你学到东西的时刻。

## 三、工单模板（我会用这些格式给你下任务）

### 需求单（模仿 Jira）
```
【需求单 PRD-001】用户下单接口
背景：用户需要能创建一笔订单
验收标准：
  1. 传入商品ID、数量，返回订单号
  2. 数量 <= 0 返回明确错误码
  3. 金额由后端计算，不信任前端传值
  4. 接口响应时间 < 200ms
优先级：P1    预估：0.5d
```

### 缺陷单
```
【缺陷单 BUG-003】创建订单后库存没扣减
环境：dev  复现步骤：1... 2... 3...
预期：库存 -1    实际：库存不变
日志/截图：...
严重级别：严重    指派：你
```

### 上线单
```
【上线单 REL-002】
变更内容：新增下单接口
影响范围：order 模块
回滚方案：git revert + 重新部署上一版镜像
上线检查项：□ 回归通过 □ 数据库脚本已执行 □ 监控无异常 □ 备份已做
```

### 复盘报告
```
【复盘】xxx 故障
时间线 / 影响面 / 根因 / 止损动作 / 改进项(带责任人和期限)
```

## 四、Definition of Done（每阶段的完成标准）

一个任务只有同时满足以下 6 条才算"完成"：
1. ✅ 代码写完并通过自测
2. ✅ 有对应测试（单元/集成至少一层），且 `mvn test` 全绿
3. ✅ 接口能跑通（Apifox/curl 实测输出留档）
4. ✅ 关键逻辑有注释、日志可追溯
5. ✅ 通过我的 Code Review
6. ✅ 记录进 `progress.md`（真实命令 + 真实输出）

## 五、每日站会（你只需回三句）

每轮开始我会问你（或我替你记录）：
1. 昨天做了什么？
2. 今天做什么？
3. 有什么阻塞？

别嫌形式主义——**这是让你形成"可汇报"的能力**，面试时会直接体现在你讲项目的方式上。

## 六、阶段 13：线上故障演练

部署完成后，我会制造真实事故，你负责处理：
1. 把数据库连接池调小 → 高并发下接口超时（练排查连接池）
2. 制造慢 SQL → 接口 RT 飙高（练 `EXPLAIN` + 加索引）
3. 线程死锁（练 `jstack` 抓死锁 + Arthas）
4. 内存泄漏 / OOM（练 heap dump + MAT）
5. 依赖服务不可用（练超时、重试、熔断、降级）

要求产出：**一份复盘报告**，就像真的线上出了事故。
